# GCP Security Review

## Scope

Apply when the repository includes Google Cloud SDK usage, Terraform for GCP, Cloud Run, GKE, Cloud Functions, IAM, Secret Manager, GCS, BigQuery, Pub/Sub, Vertex AI, or Cloud Build.

## Checks

- IAM roles, service account impersonation, key creation, workload identity, and least privilege.
- GCS public access, uniform bucket-level access, encryption, retention, and logging.
- Secret Manager access, rotation, version handling, and log exposure.
- Cloud Run and Cloud Functions ingress, authentication, environment secrets, and service accounts.
- GKE RBAC, Workload Identity, network policy, pod security, and image provenance.
- BigQuery dataset and table permissions, authorized views, and export paths.
- Pub/Sub publisher/subscriber permissions and message data sensitivity.
- Vertex AI data handling, model endpoints, prompt logging, and service account scope.
- Cloud Build triggers, secrets, substitutions, artifact signing, and deploy permissions.

## Common Findings

- Service account has `roles/owner` or broad project editor permissions.
- Public Cloud Run service exposes administrative functionality.
- Long-lived service account key committed or generated by automation.
- GCS bucket allows public access to sensitive objects.
- Cloud Build deploys with excessive permissions.

## Evidence Required

Show principal, role, resource, service account, network exposure, and exploit path.
